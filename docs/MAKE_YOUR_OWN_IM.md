# Make your own I’m

Start with **your job**, not one of our example applications. You bring the idea;
your connected AI writes the code; I’m-Ditto provides the separate build folder,
package review and workspace lifecycle. You still review and try what gets built.

The original starter is MIT licensed. Keep its two notice files when copying,
packaging or updating your app; choose separate terms for your own additions.
You can give your I’m away or sell it outside any future store. The host and
legacy dependencies have separate terms: [your creator rights](../CREATOR_RIGHTS.md).

## 1. Describe a small useful loop

Open **Make my I’m**. Give it a name and explain what goes in, what you and your
AI should be able to change, and what useful output comes out.

The exact brief for our rehearsal demonstration was:

> Keep a set list and practice notes, let me and my AI edit them, and export a session plan.

Your subject can be different. Start with one job you can test, not an entire
studio or business on the first attempt. Leave credentials and personal data out.

## 2. Build through the AI you already use

Choose **Prepare my I’m**, then **Copy build prompt**. Paste that prompt into a
Bridge-connected ChatGPT conversation, or a local Codex task with access to the
build folder. If access is missing, use the owner's normal connection controls;
the generated prompt does not grant access itself.

The prompt gives the AI the job and the exact source, instructions and package
destination. The initial starter is only a notes app: ask the AI to implement the
actual brief, test the work and explain unfinished features. Preparation and a
copied prompt do not mean the finished app exists.

## 3. Review before running

Return to the saved build under **Make my I’m → Your ongoing builds**. Choose
**Check finished package**. Read its files, declared access, dependencies and build
report. Get the source reviewed if you cannot assess it yourself.

Trust and install only the exact package you are comfortable running. These are
native applications running as your Windows user, **not OS-sandboxed apps**.
A package hash identifies bytes; it does not establish safety or authorship.

Open **My I’ms → Start workspace → Open workspace**.

## 4. Work on one shared project

Save a small fictional example through the interface. Choose **Connect my AI**
for the installed workspace and use the generated connection-check instructions.
Have the AI inspect before editing; you and the AI should see the same saved work.

For example, after saving a rehearsal containing an original placeholder song:

> Inspect my current rehearsal. Keep my existing song and its settings. Add a
> practice note, add a second song, and export the printable session plan. Use
> this installed I’m's instructions and current saved revision. Don't change
> the implementation or other apps.

Look at the actual output—not just the AI's description. Save before closing,
stop the app from My I’ms, reopen it and check that the work and exports remain.

## 5. Shape it around you

When something is missing, describe the change to the same connected AI:

> Add a Duplicate song button and the matching AI command. Give the copy a new
> identity, preserve its details, and keep my saved sessions and exports intact.
> Change the editable build source, not installed releases or live data. Test it,
> bump the version, package it and report exactly what passed and what didn't.

Stop the old app before updating. Return to the saved build, check the new
package, review the changes and approve that version. Then reopen and check both
the new feature and your existing work. If a build fails, keep the working release
and ask for the specific defect to be fixed; don't treat a test report as proof
that every possible use will work.

## What this demonstration does—and does not—show

The rehearsal desk was built through an existing Bridge-connected ChatGPT chat,
in a separate profile on the developer's PC. Supervising Codex reviewed the code,
independently reran core checks and performed acceptance tests. No source-code
correction was needed for the initial generated application. It is an assisted
creation walkthrough, **not a clean-machine or independent novice study**.

The original three examples remain the personal Bridge, video Studio and
board-game workshop. The rehearsal desk illustrates how to build something else;
it is not a fourth required download or default destination. The planned I’m-Store
is a separate future idea, not a service included in this preview.

The preserved [connection/setup video](DITTO_TUTORIAL.md) explains the earlier
connection screens. [See the completed creation journey](CREATOR_JOURNEY.md),
including actual screens, the feature update and what needed assistance. The
new creation film is assembled for visual review; it is not an uninterrupted
recording of an instant build.
