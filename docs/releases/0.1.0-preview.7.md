# I’m-Ditto · Preview 7 — launcher fix

Our first independent tester supplied a fix for the Windows dashboard launcher.
Previously it asked Explorer to open the URL and reported success without checking
that request. The portable smoke used `--no-open`, so it missed this user-facing
step. That test alone was not sufficient launch coverage.

The launcher now uses Windows' default-browser handler, waits for its response,
and reports failure with the dashboard address rather than silently succeeding.
The normal CMD launcher pauses on failure so the message can be read. If opening
fails, the host may still be running: open the printed address manually.

Thanks to the tester for the implementation and regression tests. The only change
to those supplied tests is case-insensitive discovery of Windows' PATH key.
Windows accepting an open request is not proof the page rendered; the release
check must also observe the dashboard in the browser. See [review notes](../../REVIEW.md).

## Get the fix

Download **Im-Ditto-0.1.0-preview.7-Windows-x64.zip** from the private release,
extract it and open **Launch Im-Ditto.cmd**. Node is included. Source users can
pull `main` and run with Node 22+; no dependency installation is needed.

Keep existing saved profiles and workspaces. Preview 6 and earlier releases remain
unchanged. Do not discard your previous folder or overwrite saved work.

This is a narrow launcher correction. It does not update Bridge, Chaff or
Accessibility, widen access, add a provider or change the creator workflow.
Optional reply clocks remain supported. Generated apps still run as your Windows
user, not in an OS sandbox. No private profile or credential is distributed.
