# Security and trust

I’m-Ditto is a **trusted-native preview**, not a sandbox for untrusted applications.

Generated workspaces run with your Windows account’s access. A package can be internally consistent and still be malicious. Declared permissions and file hashes do not prove safety or the publisher’s identity.

- Review code before approving a package. Ask for independent help if needed.
- Share only the folders your AI needs. Ditto does not bypass Bridge pauses or grant itself access.
- Keep credentials out of build prompts, examples, logs and screenshots.
- Back up your profile and work before updating.
- Do not expose the local Ditto host to the internet.

## Report a security concern

Email **Glyn, COO of Two Hands Network Ltd**, at [glyn@twohandsnetwork.co.uk](mailto:glyn@twohandsnetwork.co.uk), with the subject **I’m-Ditto security report**. This is the company contact for private reports; you do not need to contact the developer personally.

Include the affected Ditto version, a short description of the issue and harmless reproduction steps if available. Do not send passwords, pairing links, runtime keys, private project files or full profiles. Ask for a suitable private transfer route if further evidence is needed.

Do not post exploitable details publicly. This preview does not promise a response deadline or security certification. GitHub private vulnerability reporting has not been verified as enabled; use the email route instead.

See [the detailed boundaries](DITTO_SECURITY.md).
