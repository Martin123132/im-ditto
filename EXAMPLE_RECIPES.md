# Build your own I’m

Open **How to Ditto** in the app to read these build stories and adapt a brief into your own creation form. These are reconstructed starting briefs, not verbatim chat transcripts or claims that every generated application is automatically safe or correct. The three examples teach the method; none is required before making your own I’m.

## I’m 01 — the personal Bridge

The original I’m is the owner's own PC Bridge: a workspace shaped around how he uses AI. It is the reference example, not a third installable package in this preview. Its installed connection and personal settings remain separate and unchanged.

## I’m 02 — a music-video studio

“Build me a workspace where I can bring pictures and a music track, arrange a sequence, change captions and durations, preview it, and export an MP4. Let me and my connected AI edit the same saved project. Keep rendering local. Let me cancel a job without breaking the app. Supply an original demo and a finite command interface.”

The existing example was built in the browser ChatGPT conversation using PC Bridge. It became a package by adding a small host entry adapter and separating saved data from app code. The original app and projects are preserved separately.

Try: install I’m-Studio, start it, open the workspace, then ask your connected AI to inspect it, create a new project and prepare a short sequence. Keep the supplied Neon Atlas project as a reference. The AI can use the same controls through its documented CLI; it does not need to edit application source for each video.

## I’m 03 — a board-game workshop

“Build a workshop for inventing a tabletop game. I want editable rules, cards and a board; saved projects; a printable prototype; and an editable export. Make one original playable demo, with no borrowed characters or artwork. Expose the same operations to my connected AI and use the I’m-Ditto host contract.”

The browser ChatGPT build was explicitly constrained to a new example folder, not the host or existing Studio. The host contract was supplied before the build. Host integration and owner controls are independently checked by the supervising task.

## Your own next I’m

1. Start on **Make my I’m**. Describe the inputs, controls, AI operations and output you want. Or adapt a starting brief from **How to Ditto**.
2. Choose **Prepare my I’m**. This creates a separate editable starter and exact build prompt. Copy it into your existing connected AI session with access to that folder.
3. Have the AI implement the job and run focused tests; then try the actual interface and output yourself. Include malformed inputs, stale edits and saved-work restart.
4. The prompt includes the precise packaging command and output location. The AI returns the package and an honest build report. A starter by itself is not completion.
5. Return to the saved build request, choose **Check finished package**, review the source, declared access and report, then trust/install if appropriate. Open it through **My I’ms**. No host restart or manual catalogue copy is needed.

To refine it, work in the editable draft, increment the app version, keep saved-work compatibility, rerun tests and create a new package. Review the new bytes before updating; never modify the installed release directly.

Version changed code; never overwrite installed release files. Keep mutable work in the supplied data root. Do not place credentials, personal projects, node_modules or test evidence into a distributable package. The runtime is trusted native code, so review it before installing; the manifest is not a security sandbox.

## Evidence standard

Show the prompt, finished source, actual test result, a real app screenshot and an exported product. Label changes made during supervisory integration. Do not present a reconstruction or edited promotional video as an uninterrupted autonomous run.
